# 产品需求与行为

适用日期与总状态见 [统一入口](../README.md)。本文把产品约定、当前行为与验证边界分开；不以“代码实现了”代替验收。

## 定位、用户与场景

DorisRAG V1 是运行在本机的小型 Apache Doris 中文官方文档知识问答系统。帮助使用 Doris 的开发、数据工程及运维人员解释概念、查找规则、分析所提供的 SQL/配置/日志，并追溯回答依据。这些用户类型由已确认场景归纳，现有资料没有独立用户画像或商业化需求研究。

当前首页三个引导为“了解功能与用法”“分析报错与日志”“解决配置／功能异常”。引导只填入可编辑示例，不自动发送。版本适用性与对比可直接在同一输入框提出，不是独立入口。一个聊天输入框支持普通问题、多行 SQL、日志和配置；不要求用户选择内部检索模式或填写诊断表单。

知识范围是本地快照中的中文 `4.x`、`3.x`、`2.1` 文档。目录版本不是每个补丁版本的独立快照，不能仅凭目录推定 4.0.2、3.0.2 等具体补丁的支持情况。

## 功能与交互契约

| 需求 | 当前实现 | 验证边界 |
| --- | --- | --- |
| 基于官方资料解释知识和规则 | 共享检索、原文补取及带引用的生成流程 | 真实问题已运行；存在额外断言及证据漏用，见质量文档 |
| 复杂材料先确认用户事实、条件与查询目标 | 结构化提取及逐字材料/类型/版本校验，失败停止 | 提取阻断专项修复通过；不能保证所有复杂输入正确 |
| 必要时澄清，每次只问一个关键事项 | 待澄清状态、澄清回复接续；范围或关系无法确定时停止检索 | 原卡和多轮专项有真实记录；不代表任意省略表达均稳定 |
| 同一聊天完成多个任务 | 保存活动目标、原始材料、条件、对象及范围；新任务清理无关活动状态，保留历史消息 | CONV006 六轮同 Session 真实执行及离线回放；回答语义仍有 PARTIAL |
| 补充、纠正、追问与切换 | 规则判关系；不明确时有限关系识别；纠正更新活动事实，不把旧答案当事实 | 不承诺恢复任何历史任务；没有任意任务栈或跨会话记忆 |
| 会话历史管理 | SQLite 持久化、新建、切换、刷新恢复、删除、改名；草稿本地保存 | 浏览器回放与真实页面检查分别留存；改名业务上限 40 字符 |
| 答案依据与状态可见 | 显示引用、版本、章节、位置及原文；代码、长表格可展开 | 正文和引用有实际 UI 检查；合法编号不等于语义正确 |
| 失败可理解且可受控重试 | 保留失败状态，用户显式重试最后一个可重试回答 | 同消息新 attempt，不自动无限重发；网络请求已接受但回执丢失时先查状态 |

正常流程：进入页面并等待检索预热→选择引导或输入→接受反馈/处理中→必要澄清并接续，或检索/补取/生成→展示答案与依据→继续补充、纠正、追问或切换主题。页面约 900ms 轮询会话；当前没有流式答案，生成和检查结束后展示完整回答。

当前活动问题的原材料最多8项、合计30,000字符；超限提示精简或新建会话，保留已保存历史，不是静默滑动丢弃旧材料。多任务聊天仍可通过明确换题重置活动上下文，不能据此承诺单任务无限轮次。

## 版本规则

规则源于 10 月 24 日产品契约（本地归档：../reports/V1_PRODUCT_CONTRACT_20261024.md），当前版本解析、Session 及检索共同落实：

- 新任务无明确版本时仅查 **4.x**；同一任务沿用有效会话范围，本轮明确指定优先。
- 指定一个来源系列只查该系列；指定两版比较只查两版。只有明确全版本或未限定的跨版本请求，才扩展到已收录的三个系列。
- “其他版本”取上次实际检索范围相对于三个系列的补集；没有可用上次范围，或已查遍时，澄清，不猜测。
- 临时跨版比较不改写用户当前环境版本；纠正环境则使相关旧活动条件失效。原始用户材料中的旧版本仍留在历史记录，不能篡改原话。
- 证据不足不扩大检索范围。不把“未找到/文档未提及”写成“不支持”；补丁条件必须有正文证据。UI 输入框下方持续提示默认 4.x 及指定版本的方法。

“当前环境”“历史环境”“计划升级目标”“本轮知识来源范围”是不同字段角色。例如用户环境 2.1.4、当前比较 3.x/4.x 时，应保留 2.1.4 事实，但实际候选只能来自 3.x/4.x。

## 证据与回答要求

区分用户明确事实、文档规则、基于证据的推论、未知项；不能用模型自身的 Doris 知识补造缺失事实。存在参数、写了阈值、出现示例，不足以证明模式启用或条件具有排他性。证据支持完整条件推理时可以推理，前提和不确定性须清楚。

官方资料有冲突时保留来源、范围和条件，不强行选唯一答案。例如 3.x FE 配置和 Routine Load 文档对 `max_routine_load_task_concurrent_num` 分别写 5 和 1024：冲突识别可判通过，产品真实默认值在现有文档内不能裁定。部分列更新的固定/灵活模式与导入支持范围须分别核对，不能把模式差异本身误称冲突。

回答采用自然 Markdown，不强制审计栏目。通用解释不能冒充官方原话；Doris 专有规则、数值和结论必须有本轮证据。不得把 SQL 示例、性能示例或 PR 合并记录提升为已验证执行效果、性能承诺或确定修复版本。

## 状态与异常

| 状态/条件 | 用户应看到的行为 |
| --- | --- |
| 预热、处理中 | 状态反馈；没有把接受请求当生成完成 |
| 缺失关键条件或关系/范围不明 | 一个必要澄清，保留有效任务信息 |
| 证据不足/超出范围 | 明确证据边界，不自动跨版或编造答案 |
| 模型未配置 | 明确未生成；可用证据不伪装为模型答案；复杂分析可能无法继续 |
| 提取失败 | 提示失败，停止检索；不把长日志直接塞入 embedding 兜底 |
| 截断、非法引用、服务连接/TLS/超时错误 | 保留真实失败，显示安全可读提示；不交付为成功答案 |
| 会话忙、旧 revision、队列满、已删除 | 拒绝或恢复状态，避免重复提交/覆盖；用户可按提示再操作 |
| 服务中断后恢复 | 旧处理中回答标为中断，允许符合条件的显式重试 |

失败路径仍有未关闭的状态与推理风险，不能仅凭上述保护机制认定全部异常稳定。

## 产品边界与验收

不接入 Doris 集群执行 SQL，不自动修改配置、修复生产故障，不联网补搜知识，不提供账号/多租户/企业权限体系。不引入 Agent、Reranker、知识图谱或独立在线 Judge。Ragas 只属于评测实验，不能据此认定产品用了图谱或评测模型参与回答。

速度目标是减少无必要链路，记录接受反馈、完整耗时、理解/检索/生成及调用次数，冷热启动分开；没有已签定的数字 SLA。原契约“复杂材料至多一次分析”与当前最多一次校验失败重提取存在差异；不明确多轮关系还可能单独调用一次关系识别。该实现与代价见 [技术设计](TECHNICAL_DESIGN.md)及 [决策记录](DECISIONS.md)，不写成所有问题固定一次调用。

正式验收沿用 [22 张原始验收案例](../eval/v1_final_acceptance_20261024.json)、[冲突判据](../eval/V1_ACCEPTANCE_CLARIFICATIONS_20261024.md)及原始连续会话。要求真实 HTTP/UI/LLM/Dense、答案和实际送模证据、版本隔离、长会话、异常与时间记录；离线组件通过不能代替。三轮停止规则、未通过项及 V2 独立验收见 [质量文档](QUALITY.md)。
